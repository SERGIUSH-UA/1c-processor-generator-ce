## 🔑 Ключові знахідки

### 1. UUID генерація
- **Configuration:** 1 UUID
- **Catalog:** 11 UUID (1 catalog + 5 types × 2 UUID)
- **Document:** 9 UUID (1 document + 4 types × 2 UUID)

### 2. Мінімальна структура
- ✅ Довідники БЕЗ реквізитів працюють!
- ✅ ChildObjects містить тільки імена метаданих
- ✅ Більшість Properties - дефолтні значення

### 3. Алгоритм компіляції
```
1. /LoadConfigFromFiles → завантажити метадані
2. /UpdateDBCfg → ⚠️ створити таблиці в БД (критично!)
3. /LoadExternalDataProcessorOrReportFromFiles → згенерувати EPF
```

### 4. Типи CatalogRef
- `CatalogRef.Назва` → потрібна генерація метаданих ✅
- `CatalogRef` (універсальний) → НЕ потрібна генерація ❌

## 📚 Контекст проекту

### Проблема
Генератор НЕ може створювати EPF з CatalogRef типами:
- Designer створює порожню БД
- Немає довідників → `CatalogRef.Організації` не розпізнається
- Return code 1, EPF не створюється

### Рішення
Автоматично генерувати Configuration.xml з мінімальними метаданими довідників:
- Парсити CatalogRef/DocumentRef з YAML
- Генерувати мінімальні Catalog/Document XML
- Завантажувати Configuration в БД
- Компілювати EPF в базі з довідниками

### Очікуваний результат
✅ 100% EPF файлів компілюються (включно з CatalogRef)
✅ Вирішено проблему з `EPF_CATALOGREF_LIMITATION.md`
✅ Backward compatible (базові типи працюють як раніше)
